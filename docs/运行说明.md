# 运行说明：如何生成日报结果

> 适用版本：v1-SDD ｜ 更新日期：2026-11-10
> 相关文档：[README](../README.md) ｜ [成功标准核对表](./成功标准核对表.md) ｜ [design.md](../specs/design.md)

本文档说明如何在本地运行「智能日报生成器」并拿到生成结果，全程 3 步。

---

## 0. 前置条件

| 项 | 要求 | 检查方式 |
|----|------|----------|
| Python | 3.12 及以上 | `uv run python --version` |
| 包管理器 | uv | `uv --version` |
| 配置文件 | 项目根目录存在 `.env` | 没有则执行 `Copy-Item .env.example .env` 后按注释填写 |

`.env` 中**至少**需要配置以下内容（其余可留空，留空即跳过对应环节）：

| 配置项 | 是否必填 | 留空后果 |
|--------|:--------:|----------|
| `GITEE_TOKEN` + `GITEE_REPOS` | 二者与 GitHub 至少配一个 | 跳过 Gitee 采集 |
| `GITHUB_TOKEN` + `GITHUB_REPOS` | 同上 | 跳过 GitHub 采集 |
| `FEISHU_APP_ID` / `FEISHU_APP_SECRET` | 必填（校验项） | 启动报错 |
| `SMTP_HOST` / `SMTP_USER` / `SMTP_AUTH_CODE` | 必填（校验项） | 启动报错 |
| `REPORT_AUTHOR` / `REPORT_ROLE` | 建议填写 | 使用默认值「未命名员工 / dev」 |
| `EMAIL_RECIPIENTS` | 可选 | 只导出文件，不发邮件 |

> 安全提示：`.env` 已在 `.gitignore` 中，**严禁提交**。日志中的 token / secret / 授权码会自动脱敏为 `***`。
> 写注释时请注意：行内注释必须与值用空格隔开（`KEY=value  # 注释`），否则注释会被当作值的一部分。

## 1. 安装依赖（只需一次）

```powershell
cd D:\Code\Python\daily-report-tool-SDD
uv sync
```

装完后 `uv.lock` 锁定 httpx / python-dotenv / python-docx / pytest / ruff。

---

## 2. 生成日报

```powershell

# ② 生成「指定日期」的日报（推荐演示用，结果可复现）
uv run python -m daily_report_tool.main --date 2026-11-10
```

一条命令完成整条链路：

```
采集（Gitee / GitHub / 飞书 / Mock 并行）
  → 跨源去重 → 按状态组装三段
  → LLM 生成正文 → 空话过滤 → 三段式模板渲染
  → 入库（日报 + AI 初稿快照）
  → 导出 Markdown/Word（+ 可选邮件推送）
```

## 7. 常见现象说明（均为正常行为）

| 现象 | 原因 |
|------|------|
| 同一天重复运行，日志仍是 `id=1` | `UNIQUE(date, author)` + UPSERT：一人一天只保留一份日报，重复运行只更新内容 |
| 日志出现 `未配置 EMAIL_RECIPIENTS，跳过邮件推送` | `.env` 未填收件人，只导出文件 |
| 日志出现 `跨源去重：丢弃 N 条重复记录` | 同一批提交在 GitHub 与 Gitee 镜像仓库并存，按「标题 + 时间戳」自动去重，优先保留 Gitee 归属 |
| 日志出现 `真实数据源未返回任何记录，改用 N 条 mock 数据` | 所选日期三个真实源均无记录，自动切 Mock 维持主流程（会显著告警） |
| 飞书返回 0 条 | 应用身份 `tenant_access_token` 只能读取「应用自身创建的任务」，团队尚未产生飞书任务时为空属正常，详见 design.md ADR-007 |
| 日志出现 `LLM 已降级为纯模板方案` | LLM 超时（默认 30s）/ 不可达 / 返回结构不合规，自动降级为拼接记录摘要，日报仍会产出 |
| 数据库里同一份日报有多个版本快照 | 正文**发生变化**时才追加一版（`v1 → v2 → …`），用于回溯"上午版/补充后版"；内容与上一版相同则不会重复记录 |

## 8. 排查指南

| 报错 | 处理方式 |
|------|----------|
| `配置校验未通过：FEISHU_APP_ID…` | `.env` 缺必填项，按提示补齐 |
| `配置校验未通过：GITHUB_TOKEN/GITHUB_PAT 或 GITEE_TOKEN（至少填写一个）` | 至少配置一个代码托管 Token |
| `AuthError: Gitee Token 无效或无权限（HTTP 401）` | 检查 `GITEE_TOKEN` 是否为完整令牌值；**行内注释需与值用空格隔开或单独成行**（`TOKEN=xxx# 注释` 会把注释并进值里） |
| `AuthError: GitHub Token 无效或无权限（HTTP 401）` | 同上，检查 `GITHUB_TOKEN` |
| `EmptyDataError: 未采集到任何原始记录` | 三源全空且 Mock 也未启用时拒绝编造；检查日期是否选错、凭证/仓库是否配置 |
| `应用程序控制策略已阻止此文件（os error 4551）` | 本机 AppLocker 拦截了 `.venv` 的 exe；改用 `uv run python -m daily_report_tool.main` |
| 导出的文件在哪 | 默认 `output\`；可用 `.env` 的 `OUTPUT_DIR` 覆盖 |

## 9. 一分钟演示流程（答辩用）

```powershell
# 1) 生成指定日期日报
uv run python -m daily_report_tool.main --date 2026-11-10

# 2) 打开 Markdown 结果（也可直接在 VS Code 里打开该文件预览）
Invoke-Item output\日报_2026-11-10_tsunayoshi.md

# 3) 打开 Word 结果
Invoke-Item output\日报_2026-11-10_tsunayoshi.docx

# 4) 确认已入库
uv run python -c "from daily_report_tool.storage.database import Database; from daily_report_tool.utils.config import Config; db=Database(Config.load().db_path); print(db.get_report(1).content[:80]); db.close()"
```

讲解要点：一条命令完成「采集 → 生成 → 过滤 → 模板 → 入库 → 推送」；日志给出每步耗时；
日报三段结构固定；重复运行幂等；无数据时拒绝编造。

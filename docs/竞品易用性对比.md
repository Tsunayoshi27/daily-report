# 同类方案易用性对比测试记录

> 测试人：李佳遥（测试工程师）
> 日期：2026-11-04
> 测试目的：从普通使用者角度，测评同类"日报自动生成/聚合"工具的易用性，为
> 本项目（智能日报生成器）的功能设计和体验设计提供借鉴与避坑参考。
> 说明：部分工具受限于账号/测试企业权限，采用【实测】与【基于公开功能说明】
> 两种方式记录，证据来源已在文中标注。

## 一、被测对象
| 序号 | 工具 | 类型 | 测评方式 |
| --- | --- | --- | --- |
| A | 飞书文档/飞书机器人日报 | 办公协作平台自带 | 实测+公开资料 |
| B | 企业微信「智能文档/汇报」 | 办公协作平台自带 | 基于公开资料 |
| C | 开源日报机器人（GitHub类） | 代码提交聚合 | 实测+公开资料 |

## 二、逐项易用性测评

### A. 飞书机器人日报
1. 上手流程（模拟使用者完整走一遍）
   - 【步骤1】打开飞书开发者后台，创建企业自建应用。
   - 【步骤2】添加机器人能力、申请任务/会话相关只读权限。
   - 【步骤3】创建测试企业，安装应用，配置机器人。
   - 【步骤4】调用接口获取 token、拉取数据、组装推送。
2. 易用性观察
   - 上手门槛：高。需要开发者后台+权限+测试企业三层配置，纯业务用户做不了。
   - 配置麻烦程度：高，首次配置耗时较长。
   - 数据获取：任务、会话、消息类接口多为只读权限，相对安全，但**测试企业是独立虚拟租户，拿不到真实业务群数据**，验证真实场景困难。
   - 报错提示：权限不足时报错较明确。
3. 优点 / 缺点
   - 优点：接口体系成熟、文档齐全、能真实推送机器人消息。
   - 缺点：入门门槛高、测试环境与生产隔离，初学容易卡在权限和测试企业创建上。
4. 对本项目的启示
   - 借鉴：机器人推送做正式交付；权限用只读最小化。
   - 避坑：v1 优先用 mock 数据把主流程跑通，避免在真实飞书数据上卡进度。

### B. 企业微信「智能文档/汇报」
1. 上手流程
   - 在企微内创建智能文档，插入日报模板，成员按格式填写提交。
2. 易用性观察
   - 上手门槛：低，业务用户开箱即用。
   - 数据获取：需要成员**手动填写**，不能自动采集代码提交/任务记录。
   - 报错提示：日常使用几乎无配置报错。
3. 优点 / 缺点
   - 优点：上手快、模板友好、协作直观。
   - 缺点：无自动化采集，日报靠人肉整理，信息易漏。
4. 对本项目的启示
   - 借鉴：输出日报用"结构化模板+易读条目"，降低阅读成本。
   - 避坑：本项目核心价值是"自动采集+自动汇总"，不能做成手动填表工具。

### C. 开源日报机器人（代码提交聚合类）
1. 上手流程
   - 配置仓库地址 + 令牌（如 GitHub PAT），运行脚本按日拉取提交并汇总。
2. 易用性观察
   - 上手门槛：中。需要会配令牌、装依赖，对非技术人员不友好。
   - 配置麻烦程度：中，令牌申请和权限范围是主要障碍。
   - 报错提示：网络/令牌失效报错较常见，提示友好度一般。
3. 优点 / 缺点
   - 优点：能自动聚合代码提交，数据真实、可追溯。
   - 缺点：功能单一（多为代码维度），无任务/消息聚合，令牌配置易出错。
4. 对本项目的启示
   - 借鉴：GitHub 提交采集做成"单次拉取有耗时上限、令牌失效有明确提示"。
   - 避坑：令牌只读最小化、绝不入库；提供清晰的配置与错误说明。

## 三、横向对比汇总
| 维度 | A 飞书机器人 | B 企微智能文档 | C 开源日报机器人 |
| --- | --- | --- | --- |
| 自动采集代码提交 | 否 | 否 | 是 |
| 自动采集任务/消息 | 是(接口) | 否 | 否 |
| 自动汇总团队日报 | 需二次开发 | 否 | 部分 |
| 上手门槛 | 高 | 低 | 中 |
| 日报生成耗时 | 需开发 | 手动 | 快 |
| 是否需要写代码 | 是 | 否 | 是 |
| 适合本项目借鉴点 | 机器人推送、只读权限 | 模板化输出 | 提交采集、令牌安全 |

## 四、结论与建议
1. 本项目定位：自动采集（代码+任务+消息）→ 自动生成个人/团队日报 → SQLite 存储 → 邮件+机器人推送，与三款竞品形成差异化。
2. 借鉴：机器人推送、模板化日报、只读最小化权限。
3. 避坑：降低配置门槛（v1 允许 mock 兜底）、令牌绝不入库、真实数据与测试环境隔离要提前说明。

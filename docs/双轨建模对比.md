双轨建模对比 — UML 图 vs Markdown 规范

撰写人：穆妮莎·巴克拉木 | 日期：2026-11-09


一、各自擅长表达什么
UML 图（视觉建模） 擅长表达关系和流程。而用例图清晰展现出角色功能，泳道图展现了跨模块协作的时间顺序，类图直观展示继承树和依赖箭头，ER 图让表间外键关系一目了然。这些信息如果用纯文字描述，读者需要在脑海中自行拼凑拓扑结构，极易遗漏细节。
Markdown 规范（文本建模） 擅长表达约束和细节。接口契约中的入参类型、错误码枚举、行为约束（如"重试 3 次，间隔 1s/2s/4s"），ADL 中的备选项对比和决策理由，非功能需求中的性能指标和安全要求——这些内容如果塞进 UML 图的注释框，要么撑爆版面，要么被简化为不可读的缩写。
二、二者如何配合
在本项目中，两种建模方式形成"图定骨架、文填血肉"的互补关系：

UML 先出 — 用例图定边界（系统为谁提供什么服务），类图定模块关系（谁依赖谁），ER 图定数据落盘结构
Markdown 后填 — 每个类的方法签名、每个接口的错误码语义、每个字段的长度和枚举约束，全部在 design.md 中以表格形式精确描述
交叉引用 — design.md 引用 UML 图作为附件，UML 图中的类名和方法名与 Markdown 接口契约中的函数签名严格一一对应

三、结论
UML 帮助降低理解成本，Markdown 帮助消除歧义。单独使用任一种都会产生盲区，纯 UML 缺乏细节导致实现阶段反复确认，纯 Markdown 缺乏全局视角导致架构评审时"只见树木不见森林"。双轨并行是 SDD 方法论中"让不同角色各取所需"的关键实践。

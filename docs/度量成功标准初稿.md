# proposal 成功标准（可度量指标）初稿

> 编写：李佳遥（测试工程师） ｜ 日期：2026-11-05
> 用途：提供给需求分析师，合并进 `specs/proposal.md`，作为验收可度量指标。
> 原则：所有标准必须可验证、可执行、可判定通过/不通过，不使用"好用、流畅、
> 体验良好"等主观描述。

## 一、功能类成功标准
| 编号 | 可度量指标 | 验收方式 |
| --- | --- | --- |
| F1 | 输入合法 GitHub 只读令牌，单次拉取提交记录耗时 ≤ 3 秒 | 计时实测 |
| F2 | 输入非法/失效 GitHub 令牌，返回明确错误提示，程序不崩溃 | 运行验证 |
| F3 | 输入有效飞书任务，能正确解析出任务标题并生成对应日报条目 | 数据核对 |
| F4 | 输入有效飞书群消息，能采集并生成消息类日报条目 | 数据核对 |
| F5 | 根据采集数据生成单份个人日报耗时 ≤ 1 秒 | 计时实测 |
| F6 | 可将多条个人日报条目汇总生成一份团队日报 | 运行验证 |
| F7 | 调用飞书机器人接口，能把团队日报推送至指定会话成功 | 运行验证 |
| F8 | 使用 SMTP 能把团队日报作为邮件成功发送 | 收件验证 |
| F9 | 历史日报可写入 SQLite，且支持按日期查询已生成日报 | 查询验证 |
| F10 | 无网络时采集功能给出明确错误提示，不出现静默失败 | 断网实测 |

## 二、健壮性与容错类
| 编号 | 可度量指标 | 验收方式 |
| --- | --- | --- |
| R1 | 采集接口超时（≥ 5 秒）时自动重试，重试次数 ≤ 3 | 日志核对 |
| R2 | 某一数据源（如飞书）不可用时，不影响其他数据源采集 | 单源停用实测 |
| R3 | 系统连续运行 30 分钟无崩溃、无内存异常增长 | 长时间运行观察 |

## 三、范围约束（v1 明确不做，写入 proposal 排除项）
| 编号 | 排除项 |
| --- | --- |
| S1 | 不提供 Web 可视化页面 |
| S2 | 不做 AI 智能摘要/自动总结 |
| S3 | 不做考勤打卡数据采集 |
| S4 | 不涉及真实生产环境大流量，仅支持小组规模使用 |

## 四、性能与可靠性基线（估算，待架构师复核）
| 指标 | 建议值 |
| --- | --- |
| 支持并发用户 | ≥ 5 人（小组规模） |
| 单次采集数据量 | 单日提交 ≤ 100 条可正常处理 |
| 数据持久化 | SQLite 文件，日报可回溯 ≥ 30 天 |

## 五、说明
1. 本初稿为第一版，供需求分析师合并进 `specs/proposal.md` 并补充业务细节。
2. 若某些数据源使用 mock 模拟兜底，对应指标验收改为"对 mock 数据同样成立"。
3. 性能阈值（并发、数据量、耗时上限）建议在评审会上与架构师对齐后定稿。

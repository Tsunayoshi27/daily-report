# 同类方案易用性对比测试记录

> 测试人：李佳遥（测试工程师）
> 日期：2026-11-04
> 测试目的：从普通使用者角度，测评同类"日报自动生成/聚合"工具的易用性，为
> 本项目（智能日报生成器）的功能设计和体验设计提供借鉴与避坑参考。
> 说明：部分工具受限于账号/测试企业权限，采用【实测】与【基于公开功能说明】
> 两种方式记录，证据来源已在文中标注。

## 一、被测对象
| 序号 | 工具 | 类型 | 测评方式 |
| --- | --- | --- | --- |
| A | 飞书日报 | 办公协作平台自带 | 实测+公开资料 |
| B | 企业微信「智能文档/汇报」 | 办公协作平台自带 | 基于公开资料 |
| C | 飞报大师 | 日报管理 SaaS | 基于公开资料 |

## 二、逐项易用性测评

### A. 飞书机器人日报
1. 上手流程（模拟使用者完整走一遍）
   - 【步骤1】打开飞书开发者后台，创建企业自建应用。
   - 【步骤2】添加机器人能力、申请任务/会话相关只读权限。
   - 【步骤3】创建测试企业，安装应用，配置机器人。
   - 【步骤4】调用接口获取 token、拉取数据、组装推送。
2. 易用性观察
   - 上手门槛：高。需要开发者后台+权限+测试企业三层配置，纯业务用户做不了。
   - 配置麻烦程度：高，首次配置耗时较长。
   - 数据获取：任务、会话、消息类接口多为只读权限，相对安全，但**测试企业是独立虚拟租户，拿不到真实业务群数据**，验证真实场景困难。
   - 报错提示：权限不足时报错较明确。
3. 优点 / 缺点
   - 优点：接口体系成熟、文档齐全、能真实推送机器人消息。
   - 缺点：入门门槛高、测试环境与生产隔离，初学容易卡在权限和测试企业创建上。
4. 对本项目的启示
   - 借鉴：机器人推送做正式交付；权限用只读最小化。
   - 避坑：v1 优先用 mock 数据把主流程跑通，避免在真实飞书数据上卡进度。

### B. 企业微信「智能文档/汇报」
1. 上手流程
   - 在企微内创建智能文档，插入日报模板，成员按格式填写提交。
2. 易用性观察
   - 上手门槛：低，业务用户开箱即用。
   - 数据获取：需要成员**手动填写**，不能自动采集代码提交/任务记录。
   - 报错提示：日常使用几乎无配置报错。
3. 优点 / 缺点
   - 优点：上手快、模板友好、协作直观。
   - 缺点：无自动化采集，日报靠人肉整理，信息易漏。
4. 对本项目的启示
   - 借鉴：输出日报用"结构化模板+易读条目"，降低阅读成本。
   - 避坑：本项目核心价值是"自动采集+自动汇总"，不能做成手动填表工具。

### C. 飞报大师
1. 上手流程
   - 注册飞报大师账号（SaaS），创建项目/团队，添加成员。
   - 成员通过 PC Web 或微信小程序按模板字段填写日报（今日完成、明日计划、风险阻塞），精确到小时级别。
   - 领导端可逐条审核报告，进行打分、评论或驳回。
   - 系统自动按日报汇总周报、按周报汇总月报，支持月度/季度/半年/年度周期性汇总。
2. 易用性观察
   - 上手门槛：低。SaaS 注册即用，模板化填写界面直观，微信小程序降低移动端填写门槛。
   - 配置麻烦程度：低，无需技术部署与配置。
   - 数据获取：所有日报内容完全依赖员工手动填写，无任何自动数据采集能力，无法接入 GitHub / 飞书 / Jira 等第三方数据源自动生成条目。
3. 优点 / 缺点
   - 优点：双端覆盖（PC Web + 微信小程序）；日报→周报→月报自动汇总链路独特；领导打分/评论/驳回形成管理反馈闭环；精确到小时的工时与项目挂钩；SaaS 开箱即用，零技术门槛。
   - 缺点：纯手动填写，无自动采集，日报质量依赖个人投入；无 AI 生成与防伪约束机制；不支持私有化部署，数据存储在厂商云端；管理功能以审核打分/驳回为主，缺少全员日报自动汇总与风险提炼能力。
4. 对本项目的启示
   - 借鉴：结构化模板字段设计（今日完成/明日计划/风险阻塞）；日报自动汇总链路的用户体验值得参考。
   - 避坑：本项目核心价值是"自动采集 + 自动生成"，绝不能做成纯手动填表工具。

## 三、横向对比汇总
| 维度 | A 飞书机器人 | B 企微智能文档 | C 飞报大师 |
| --- | --- | --- | --- |
| 自动采集代码提交 | 否 | 否 | 否 |
| 自动采集任务/消息 | 是(接口) | 否 | 否 |
| 自动汇总团队日报 | 需二次开发 | 否 | 是(日→周→月) |
| 上手门槛 | 高 | 低 | 低 |
| 日报生成耗时 | 需开发 | 手动 | 手动 |
| 是否需要写代码 | 是 | 否 | 否 |
| 适合本项目借鉴点 | 机器人推送、只读权限 | 模板化输出 | 汇总链路、审核反馈 |

## 四、结论与建议
1. 本项目定位：自动采集（代码+任务+消息）→ 自动生成个人/团队日报 → SQLite 存储 → 邮件+机器人推送，与三款竞品形成差异化。
2. 借鉴：机器人推送、模板化日报、只读最小化权限。
3. 避坑：降低配置门槛（v1 允许 mock 兜底）、令牌绝不入库、真实数据与测试环境隔离要提前说明。
